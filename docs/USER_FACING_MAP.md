# User-facing map - Shresth Masala Industry Management System

Generated by walking `backend/app/routes/*.py`, `backend/main.py`, the route decorators, and every
`UI.api` / `UI.download` / `fetch` call under `frontend/`. Re-run the generator rather than hand-edit.

**Totals:** 187 HTTP endpoints, 26 HTML pages, 3 shared JS files, 52 tables, 70 money columns, 26 scale-3 quantity columns, 39 startup column migrations.

Gate legend: `public` = no token. `auth` = any signed-in role (viewer is GET-only). `write` = non-GET (viewer blocked, data_entry blocked on DELETE). `editor` = also needs Editor Mode on via `POST /auth/editor-mode`. `admin` = role `admin` only.

## 4. Persistence layer

Tables (52): `attachments`, `audit_logs`, `hsn_codes`, `application_settings`, `backup_records`, `import_reports`, `dashboard_shares`, `saved_reports`, `cash_movements`, `customers`, `suppliers`, `employees`, `attendance`, `leaves`, `salary_payments`, `employee_advances`, `deductions`, `expense_categories`, `expenses`, `finished_product_stock_movements`, `notification_rules`, `notification_logs`, `print_footers`, `product_categories`, `products`, `packaging_sizes`, `product_formulations`, `product_formulation_steps`, `size_rate_history`, `product_workflow_stages`, `production_entries`, `production_consumed_materials`, `production_outputs`, `production_stage_entries`, `production_wastage`, `purchase_invoices`, `purchase_invoice_items`, `supplier_payments`, `raw_material_categories`, `raw_materials`, `raw_material_stock_movements`, `sales_challans`, `sales_challan_items`, `sales_invoices`, `sales_invoice_items`, `customer_payments`, `document_sequences`, `users`, `dashboard_preferences`, `roles`, `permissions`, `role_permissions`.

- Schema is hand-rolled, no Alembic. `init_db()` calls `create_all` then `_ensure_columns()`
  (`backend/app/core/database.py:190`), which ADD COLUMNs idempotently at every start.
  `_ensure_production_pack_columns()` covers `production_entries.packed_at` and
  `movement_date` on both stock-movement tables.
- Soft delete: `is_active` on masters (customers, products, raw materials, print footers, users);
  `is_archived` on documents (sales challans, customer payments, purchase invoices,
  supplier payments, production entries, expenses, salary payments). FK enforcement is ON,
  so deleting a referenced parent raises - archive instead.
- Money: every `Numeric(_, 2)` column is quantized HALF_UP by the `before_flush` hook;
  scale-3 quantities are deliberately left alone.
- Challan stock has exactly one writer: `services/stock_posting.py::post_challan_sales_movements`,
  called by confirm and the Excel importer.
- Timestamps: `_ist_wall()` (naive IST) everywhere on persistence paths; the frontend parses
  naive values as IST. `test_ist_everywhere.py` pins this.

## 5. Integration verdict (hand-written analysis, 2026-10-27)

Method: 187 backend routes were matched against every literal `UI.api(...)` / `fetch(...)`
URL in `frontend/pages/*.html` and `frontend/js/*.js` (246 call sites), plus a method-aware
pass that pairs each URL with the `method:` in the same call. URLs assembled by string
concatenation are matched after re-joining the base path, so the counts below are lower
bounds, not guesses.

### 5.1 Chains that are complete
Auth/users, customers, suppliers, products + packaging sizes, raw materials, purchase
invoices + supplier payments, production entries, sales challans, expenses, reports,
settings, backup, import/export. Each has a page, a nav entry, handlers that name real
routes, and the route writes through to a table that exists in `models/` and is covered by
`_ensure_columns()`. No schema/API drift found in these lanes.

### 5.2 Chains that are broken end to end
| Feature | Frontend entry point | Backend | Failure |
|---|---|---|---|
| Record a customer payment | `challans.html:399` "Payment Received", `openPaymentForm` 1833, save 1874 | none - no `/payments` router, though `rbac_guard` at `main.py:568` already whitelists `/payments*` | 404 at save; money never lands in `customer_payments` |
| List / edit / delete payments | `challans.html:1081,1648,1660,1910,1945` | none | 404 |
| Invoices list + detail | `invoices.html:344,354` | only `POST /sales-invoices` (sales.py:381), which no page calls | page renders empty |
| Invoice PDF / e-mail | `invoices.html`, `challans.html:1443-1475` | none - no invoice serializer, PDF, or mail route exists | 404 |
| Global search box | `app.js:415` `GET /search?q=` | `search_all` not defined | 404, no results ever. Tests pin the contract: `m.search_all(db, q, include_payments=?, include_expenses=?)` |
| Payroll run | `payroll.html:223` `GET /payroll/run?period=` | `POST /payroll/run` (employees.py:274) | 405 |
| Attendance / advances / deductions / leaves per employee | `payroll.html:309-411` nested `/employees/{id}/...` | flat `/attendance`, `/leaves`, ... with `employee_id` query param (employees.py:120-234) | 404; leave approve (`/leaves/{id}/decide`) has no route at all |

Consequence: the sales-to-cash chain stops at the challan. Goods leave stock, but the
receivable is never recorded and no invoice can be produced, so any report that aggregates
`customer_payments` under-reports collections for every challan confirmed in the UI.

### 5.3 Backend-only surface
`POST /sales-invoices` and `POST /customer-payments` exist but nothing calls them. They
were presumably the intended targets of the missing `/invoices` and `/payments` pages.
Treat them as the implementation seam: adding thin list/update/delete routes over the
same service functions closes 5.2's first four rows.

### 5.4 `backend.main` re-export block
`main.py:318-462` aliases 120 handlers onto the module for the test suite. The
suite calls about 440 distinct `main.<name>` symbols; at least 50 genuine names are missing
(`search_all`, `reports_summary`, `list_invoices`, `update_payment`, `reopen_challan`,
`list_raw_materials`, `undo_last_import`, ...). This explains a large share of the suite going red across unrelated files. Fixing the
alias block is a one-file change. It is not the only cause - see 5.6 - so expect the
suite to stay red afterwards; the alias fix only makes the remaining failures legible.

### 5.5 Caveats
- The "endpoints with no frontend caller" table in section 3 is literal-call-site only.
  A URL built from a variable will not appear there; verify before deleting a route.
- Method mismatches were screened manually. Seven of eight flagged pairs were `/`-prefix
  artifacts of concatenated URLs; only `GET /payroll/run` is real.
- This map reflects code, not the shipped build. `_internal/frontend/` in each deployment
  folder may lag the repo; re-grep the packaged path before claiming a fix is live.
